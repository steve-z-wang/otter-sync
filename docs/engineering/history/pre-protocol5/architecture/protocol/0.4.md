# Protocol 0.4: admission, coverage and settlement

Historical carrier reference. Current behavior is owned by [protocol 5](https://github.com/zanminwang/axton/blob/71b14195b897bc8a42f19e0a83d59dfe8fc76677/docs/engineering/architecture/protocol/0.5.md). This page does not promise support for old local files or an alternate current API.

## 1. Introduction and goals

The shared contract lives in [`axton_core::v04`](https://github.com/zanminwang/axton/blob/v0.4.2/crates/core/src/protocol_v04.rs). This document owns admission, coverage and settlement requirements; component documents describe their runtime implementation. Internal legacy compatibility paths do not provide a 0.3 database migration.

One client exclusively owns one physical SQLite file and follows one Stream. Model content positions, historical delivery evidence, membership and complete Stream progress are separate facts. Ordinary reads never manufacture position evidence.

## 3. Context and scope

`StoreBinding {backend, viewer, stream, contract}` is immutable. Backend/viewer are stable authenticated identifiers, not credentials. Contract is an application namespace. The materialization context identifies expanded read descriptors and the host's explicit Loader projection generation; schema reconciliation changes that context without replacing the binding. An incarnation is the persisted Store lifecycle/reset identity. Normal file reopen, crash recovery, credential refresh and reconnection retain it; explicit Store reset changes it. Ephemeral connection/actor generations remain local and must not be substituted into wire contexts. Authentication remains the host's responsibility: a Stream name does not authorize a viewer.

Every envelope requires protocol `4`; checked `decode`/`encode` validate nonblank identifiers, canonical call UUIDs, safe integer counters and structural invariants. v0.4 custom deserializers strictly check nested key/completion/outcome envelope members while retaining legacy codec behavior and opaque application identity/state/result fields. Application identities/states still require schema-aware normalization by consumers. Binding/context is metadata, never a Model field.

| DTO | Consumer responsibility |
| --- | --- |
| `ReadIntent`, `FetchIntent`, `ReadResponse` | Query/Fetch correlation, boolean storage mode, active-context admission |
| `ReadRecord` | Required `cursor:null`, snapshot state or absence; no stamp |
| `StreamRecord`, `StreamChange` | Positive cursor content or explicit membership Remove |
| `RecordEvidence` | Persist historical G, current content/deletion protection and membership together with rows |
| `ManifestPage`, `BootstrapCoverage` | Fixed identity-ordinal coverage, then fixed tail handoff |
| `DeltaPage`, `CommitUnit`, `PageProgress` | Ordered atomic units and exact durable-prefix resume |
| `MutationIntent`, `MutationReceipt`, `SettlementTarget` | Frozen durable intent, definitive outcome and exact server-visible target evidence |

The [shared wire fixture](https://github.com/zanminwang/axton/blob/71b14195b897bc8a42f19e0a83d59dfe8fc76677/fixtures/protocol/0.4.json) is consumed by the [core contract tests](https://github.com/zanminwang/axton/blob/v0.4.2/crates/core/tests/protocol_v04.rs). Server, client and language bridge tests should consume those same bytes.

## 4. Solution strategy

### G1: content and membership admission

Query/Fetch snapshots contain an explicitly required null cursor. Both modes return the invocation snapshot. `store:true` applies `ReadRecord::disposition` at local commit: missing snapshots never delete, current authority or a real tombstone blocks cache replacement, and other non-null snapshots can fill cursor-null state. Historical G alone does not block reads. `store:false` stores request/result completion metadata only. Default/true canonicalize identically; false is a distinct intent/cache key. Once returns the saved invocation result without applying Models or rerunning explicit track.

`RecordEvidence` separates per-context historical positions from optional current protection and the latest membership position. Direct writes clear live-content protection while retaining G; existing authoritative absence protection remains. Pending overlays never clear base evidence. Older/equal authority within a context is duplicate, including after direct writes. Across contexts, positions cannot regress. Same-position new-context admission is `Rematerialize`, allowing new fields without clearing historical G.

Remove keeps content and G, releases current **live-content** protection, and retains real deletion protection. It does not assert Loader absence. Re-track allocates a new position; repeated live track does not. An older Remove cannot undo newer enrollment/authority. After Remove, an accepted private settlement can leave B as cursor-null state. A late unversioned Query may replace B under cache best effort; it cannot overwrite re-tracked authority or resurrect a protected absence.

Content/position correspondence needs more than a shared transaction. PostgreSQL uses a persisted namespace row updated inside the Serializable transaction. Publications and versioned authority materialization acquire this fence **before** business work or canonical position/content reads and hold it through commit. Ordinary read-only Queries remain concurrent. Explicit tracking upgrades such a read to the fence; an intervening writer causes the entire handler transaction to retry and discards its previous output. Application-owned transactions acquire the fence before relevant work; publishing after unfenced writes cannot repair a stale snapshot. Narrower locks would require complete projection dependency closure.

Every change affecting a viewer's Loader output must invalidate every affected live pair in the same commit. External/time-dependent inputs must be materialized and published, or explicitly change projection generation and rematerialize. Missing publication is a host contract violation. Shared Streams do not justify sharing viewer projections.

Same-position rematerialization updates the authoritative base using new descriptors and replays surviving direct/pending operations. A visible direct layer keeps its content cursor null. Retained-contract full-row operations update only their declared fields, preserving newly added base fields. A genuinely higher Stream position still retires direct state. Old direct responses are refused; frozen Mutation outcome reconciliation has its own admission path below.

### G2: finite bootstrap

After Bootstrap explicitly tracks its range, one transaction persists its outcome, start N and an immutable sorted manifest of live bootstrap-marked identities, not all payloads. Identity storage is paged and bounded by host capacity; capacity failure rolls back the run instead of returning partial success. Retry does not rerun a committed handler.

`ManifestPage` answers every ordinal in its exact range with current content, authoritative null or membership Remove. Keys cannot escape when the compacted log moves them beyond N or H. Rows, evidence and coverage commit atomically; Loader/constraint/storage failure leaves that unit uncovered. Manifest keys survive removal/deletion. A removed key is explicitly covered without claiming current content authority.

After complete manifest coverage, capture one fixed tail H >= N. `BootstrapCoverage::set_tail` rejects premature capture and replacement; complete requires covered==total and contiguous C>=H. Unrelated writes after H do not move the goal. X@50 moving to101 then150 is resolved by its fixed ordinal, never by merely observing C>=101. An empty manifest still obtains H; filtered delta units can prove an empty prefix.

A run survives restart until completion/cancellation acknowledgment. Administrative eviction returns `bootstrap_expired`, with an explicit replacement run and preserved local evidence, never silent completion. Rematerialization includes held authoritative identities and absences; removed tombstones retain protection and can be covered by Remove. No age-based G/tombstone collection in 0.4.

### G3: owned mutation completion

A frozen `MutationIntent` retains its original context, Model read versions and canonical args. A receipt binds its call UUID and domain-separated intent digest to the original context. `MutationReceipt::admit` allows supported schema rollover only when the binding and persisted incarnation match and the **exact frozen intent is loaded from the active database's durable queue**. Detached old handles after Store reset are not authorization. Old direct responses still require the active materialization context and persisted incarnation. Reset rejects old receipts as well as reads; normal reopen reconstructs byte-equivalent context so retained Bootstrap/DeltaPage plans can resume. Closed/detached handles still require runtime lifecycle checks and a durable queue lookup.

`validate_targets` compares against server-visible optimistic slot identities derived from the retained Mutation descriptor/arguments. Device-only callbacks/companions never enter this server manifest: the server cannot read a local Draft. Client ownership plus accepted/refused outcome settles companions in their original local order. Failure removes only that call's ownership; success finalizes companions as device-only operations.

| Case | Proof and completion |
| --- | --- |
| Current tracked or explicitly newly tracked target | Required cursor installed, or later installed Remove plus frozen same-transaction owned fallback, before Call completion |
| Never tracked / previously removed / only other Streams published | Immutable call-private transaction readback, no positive cursor; finalize owned null state without track/G/C |
| No-op / no Model targets | Empty manifest, definitive outcome and local ownership cleanup; companions can still exist locally |
| Rejected | No success targets; remove only owned operations and persist refusal/completion |
| Server accepted, local reconciliation fails | Persist accepted-awaiting-settlement; retry locally, never reinterpret as business rejection |

Private evidence has two dispositions: `FinalizeOwnedNull` when no protection exists, or `AcknowledgeProtected` when authority/tombstone wins. It never enters generic authority admission or clears guards. Later independent direct/owned operations remain later. A tracked target freezes `{key, cursor, fallback: ReadRecord}`: fallback is same-key canonical readback from the accepted transaction with required null cursor. Normally its required Stream authority must be installed; ordinary Fetch cannot discharge it. If membership Remove at a **later** position is installed before the content arrives, the compacted log may have permanently replaced that content event. The receipt then uses its frozen fallback solely to finalize call-owned null state; if current authority/deletion protection exists, it acknowledges without overwrite. Remove does not become G or content evidence. Re-track/new authority wins, and later independent local operations keep their order. For a retained old-context Stream target, active-context evidence can qualify only after consumers validate identity/field compatibility through retained descriptors; the receipt cannot establish that compatibility or install old-schema authority itself.

Receipt before Stream leaves accepted-awaiting until required authority commits or the later-Remove fallback becomes eligible; Stream before receipt permits finite completion from installed evidence without overwriting newer state. Call waits only for its initiating Store, never another client. Mixed targets/ownership reconciliation validate the final projection atomically.

### G4: complete units and constraints

A `DeltaPage` is an immutable context/ID/range and ordered units. `through` proves a complete handled prefix, never merely max(record.cursor). A later unit cannot contain a change below the previous unit's through. Earlier units may include ahead-of-prefix records needed for constraints; G can advance before C. Such records are bounded by the page's observed `head`, rather than its covered `to`.

`PageProgress` stores next unit, C and a domain-separated SHA-256 canonical-plan digest. The hash binds protocol, binding/context, range, unit order and payload; mutation-intent hashes use a separate domain. The server/client must retain the bounded immutable plan or its staged source across retry. Expired plans produce explicit `plan_expired` without advancing C; the client can obtain a replacement starting exactly at persisted C while retaining earlier G. A changed plan cannot resume under the original plan ID. No full payload duplication in progress metadata.

Each unit's rows, evidence, ownership reconciliation, safe C and next-unit marker commit together. A failed unit/restart resumes from the durable prefix. Unique transfers, owned-operation dependencies and declarative cascades must form appropriate atomic commit groups, even across ordinary page boundaries. Existing AXTON references are navigation/cascade/dependency metadata, not domain foreign-key existence constraints; partial caches need not contain referenced parents. Internal queue SQL foreign keys retain their existing transactional enforcement. Stage final values, clear conflicting old values, validate final constraints and replay pending before commit. Explicit `constraint_group_capacity` blocks progress; disk staging can avoid in-memory truncation. Untracked relation targets are not implicitly enrolled; missing local referenced rows alone do not block a unit. Hosts explicitly publish each changed/deleted identity; the engine does not invent parent-cache completeness policy.

Declarative local cascade is device-only: it clears live-content protection but creates no child authority tombstone. Backends publish every canonical child deletion explicitly. For ordinary cursor-null reads only, `ReadRecord::disposition_with_relations` checks declared `onTargetDelete:delete` references in the returned snapshot against parent evidence read in the same local transaction. A **current Stream tombstone** for a referenced parent returns `DeletedParent`, suppressing that child cache write without inventing child authority. Missing/unloaded or locally deleted parents, null references and `onTargetDelete:none` do not suppress it. `store:false` still returns the snapshot. A later Stream child record has its own authority and does not pass through this ordinary-read guard; backends must explicitly publish canonical child absence. There are no onStore callbacks or replacement observer-write hooks.

## 6. Runtime view: consumption examples

SYN-7 server: normalize authenticated request and retained descriptors; acquire publication fence before handler; persist Mutation receipt and manifest rows inside the business transaction, including canonical null-cursor fallback on every tracked settlement target. Build `MutationReceipt` targets from slot identities; encode only after definitive target completeness checks. Resolve a `ManifestPage` by saved ordinal keys under the versioned Loader fence. Build immutable `DeltaPage` units from complete constraint groups.

SYN-8 client: `decode::<ReadResponse>` then `admit` against requested and active contexts; decide each record at commit using `disposition_with_relations` with this transaction's parent tombstone evidence. For delta, admit active page context, construct/load `PageProgress`, apply the exact next unit and persist `commit` in the same transaction. For manifest, apply rows and `commit_page` together, then capture/install tail. For Mutation, fetch the frozen intent from this database's queue, `admit` receipt, derive/validate server-visible keys and evaluate settlement dispositions. For `FinalizeOwnedNull`, use `SettlementTarget::owned_snapshot` at the owned operation's original order; a later-Remove fallback never installs G/C or defeats a newer protected base. Only then reconcile actual owned rows/companions and mark Call complete. Evidence helpers never replace row/constraint transactions.

SYN-9 SDK/ABI: transmit these DTOs unchanged, normalize default store=true, retain call UUID/canonical intent through retries, and forward definite request completion only after engine commit. Do not implement a separate cursor, settlement or constraint state machine. Native open validates binding and obtains an exclusive OS file lock using canonical path/file identity before coordination writes; alias/cross-process opens return `store_in_use`. Credentials refresh leaves binding unchanged; normal close releases the lock and retains progress/work.

## 10. Quality requirements and evidence

Core tests cover null/legacy cursor rejection, canonical read modes, protected vs historical evidence, Remove/re-track ordering, private and tracked-to-Remove fallback dispositions, known-parent deletion read guards, strict nested envelopes, compatible context admission, exact targets, moving/removed manifest coverage, unchanged-position evidence, canonical plan digest and partial-prefix recovery. See test names and shared fixtures for exact boundaries.

Runtime acceptance remains SYN-7/8/9 work: PostgreSQL fence and manifest persistence, atomic SQLite ownership/pending reconstruction, compatible descriptor projection, cross-page constraint closure, file exclusivity, process interruption and actual language/native packages. The core suite is structural/admission evidence and does not claim V01–V13 integration success.
