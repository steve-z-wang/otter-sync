The independent [requirements model](https://github.com/zanminwang/axton/blob/v0.4.2/crates/sim/src/oracle04.rs) imports no production admission, DTO, storage or settlement implementation. Run `cargo test -p axton-sim --locked`; the `oracle04` test target compares 122 complete snapshots across eleven scenarios. A passing reference-model run checks agreement between the authored expectations and model, **not production engine acceptance**.

`Scenario::verify_with` accepts a `ScenarioAdapter`. The native adapter below executes separately authored production-compatible events and exposes normalized committed storage. Expected state remains in the trace, independent of both implementations. The verifier compares every step, including after failures, and reports scenario plus step. `verify` uses only the requirements model.

Five additional counterexample tests cover immutable captured tails, ahead-of-prefix positions bounded by the page head, original operation ownership after newer authority, private receipt ordering and active-materialization evidence for retained receipts. These also execute only the independent model.

Each snapshot includes visible rows, base state, current content cursor/deletion guard, per-materialization G, membership, ordered direct/pending layers, queue, Call state/result/frozen context, read modes and returned snapshots, C, immutable page plan/next unit, Bootstrap coverage/tail, binding/incarnation and open state for every Store. Expected changes are concise: rows/base/returns/requests/calls/layer arrays/progress/Bootstrap replace their entire container; other objects merge. Omitted fields retain their previous expected value, but comparison always uses the complete state.

## Actual native adapter and transport runner

`cargo test -p axton-sim --test native04 --locked` drives [two native traces](https://github.com/zanminwang/axton/blob/v0.4.2/integration/0.4/native-scenarios.json), fourteen steps, through the actual common binding actor and SQLite. These expectations are authored independently. They cover two files on the same Stream, ordered direct writes, real file reopen, an empty proven Delta prefix, Stream content and persisted tombstone evidence. They do not translate all 122 symbolic steps or simulate a backend. Initial empty manifest and ACK answers are explicit authored host effects; later changes enter the real socket/Delta carrier. No helper installs authority and no SQL writes C.

The [adapter](https://github.com/zanminwang/axton/blob/v0.4.2/crates/sim/tests/support/native04.rs) has fixed normalization: Entry version 1 with string id/text, UUID `01890f47-1234-7123-8123-000000000001` maps to `x`; the schema materialization digest maps to `s1`; each Store's retained incarnation maps to `inc1`; temporary physical file paths map to their trace path. Context comparison occurs before mapping. A page digest maps to its page-id symbol only after retaining and checking the original digest for immutable replay. SQLite snapshots include rows, every evidence/base/generation field, local layers/writes, owned and pending operations, queue, Calls/completions, saved reads, page payload/progress and manifest coverage, plus Store binding/context/C/lifecycle. JSON columns are decoded; no expected-state mask selects actual fields. Closed Stores retain the last committed snapshot; reopen queries the actual file again.

In that release, `bash integration/0.4/run.sh`, also called by `scripts/test.sh`, built the Node addon and TypeScript host packages, creates a disposable PostgreSQL cluster, starts the real backend HTTP/WebSocket listener and forks a [native actor child](https://github.com/zanminwang/axton/blob/v0.4.2/integration/0.4/actor-child.mjs) per Store. The [host driver](https://github.com/zanminwang/axton/blob/v0.4.2/integration/0.4/native-host.mjs) executes HTTP/socket/timer effects, holds selected already-computed responses or frames, and submits tasks/read-only SQL. It implements no authority or settlement logic. Committed-condition waits use a twenty-second elapsed deadline and actual SQL/event progress, never fixed sleeps.

The eighteen [production tests](https://github.com/zanminwang/axton/blob/v0.4.2/integration/0.4/production.test.mjs) assert historical target 57 behind initial C80 with a concurrent public Bootstrap; frozen exact retry after accepted response loss and SIGKILL under added Model/current descriptor; Query true/false once separation and stale Fetch after Stream tombstone; independent server transactions transferring UNIQUE values; a fixed tail while one identity moves again; a real deferred SQLite COMMIT refusal with durable accepted-awaiting, later direct content and SIGKILL/reopen; reset fencing an old response while another same-Stream file survives; Alice/Bob viewer-specific projections and rejection of Bob authentication carrying Alice context; bounded adaptive manifest coverage under a persistent Loader refusal; a paused real Query handler while sync and local commits progress; and a declared parent deletion cascade followed by a delayed child Fetch. Fault injection adds a deferred constraint/trigger only: production performs the failing COMMIT. Call and record evidence is read from the real databases. Additional cases distinguish untracked, other-Stream-only and tracked no-op Mutation targets, preserve a later direct edit after delayed private settlement, settle a no-Model Mutation, and deliver historical Remove before a held receipt both with and without a later direct edit. Historical Remove is exact retained storage compatibility evidence published under the real PostgreSQL fence; it is not a current public untrack API. Closing and reconnecting the actual socket obtains the compacted change through ordinary catch-up.

These are native-engine transport tests, not installed generated TypeScript/Dart SDK proofs. The full transport UNIQUE case uses separate release/acquire server transactions, forces real transport retry down to a one-ordinal acquire page, asserts the later release identity arrives as its companion, and checks the actual SQLite secondary UNIQUE index and atomic final rows. The moving-key fixture uses positions 1/2/3; the exact N100/X50/H101/to149 counterexample remains symbolic/component evidence. Physical aliases/process duplicate opens, async Mutation scopes, the remaining declarative cascade variants and complete language observer/handle isolation remain their component/package obligations. The fixed transport traces do not provide seeded or benchmark coverage; the bounded local generator and scoped actor measurements below are separate evidence.

## Event vocabulary and limits

`stream` installs record position; it does not itself advance C. `remove` changes membership without installing content/G or deleting the row. `direct` and `enqueue` append ordered layers. `receipt` retains acceptance independently of local reconciliation; `settle` waits for required compatible active-context authority or later Remove, using its frozen canonical `state` solely at the original owned layer's order and only if newer Stream authority has not superseded that operation. The same original-generation condition governs retained companions. Null `cursor` denotes private settlement. `failLocal` injects failure after staging but before the atomic commit. `refuse` removes only that Call's owned layers.

`read.storeResult` maps to the public `store` option; its name differs because `event.store` identifies the physical Store in the trace. Missing mode means true. Returned snapshots are independent of stored rows. `cascadeParents` lists resolved parent keys from *declared delete-cascade schema relations*, not all references. Cascade child deletion is explicit in a transaction event, so this small model does not claim to implement schema traversal. Missing referenced cache rows are allowed.

`page` freezes an exact plan; `unit` commits only its next group and proven `through`, checking any declared final-projection `uniqueField`. Atomic groups may contain record positions ahead of their safe prefix, bounded by `page.head` (omitted in older symbolic fixtures means `to`); later units may never reveal changes at/below a previously committed prefix. `bootstrap` freezes keys; `item` covers an exact next ordinal with content or Remove; `tail` captures a fixed H only after coverage and rejects any attempt to replace H; completion also requires actual C to reach H through proven delta units. Capturing H never advances C. Keys here are readable symbolic identities, not wire `RecordKey` encoding. `restart` preserves symbolic durable state; `close`/`open` retain lifecycle state. These are trace obligations for adapters, not evidence of disk persistence. Paths are symbolic strings; the model cannot prove canonical filesystem aliases or cross-process exclusivity. Model capacity, request cancellation, auth, Loader fences and transport are outside it.

## Existing guarantees and required real evidence

The old simulation runners remain intact. Their passing results still exercise the baseline stamp/Load runtime, not 0.4. Retain A1 ownership replay, A5 failure atomicity, distribution convergence/publication coverage and restart/isolation assertions. Replace A2 whole-page advancement with proven committed units; replace A3–A4 receipt authority with tracked/private/fallback settlement; replace D2/D4 global stamp ordering with one-Stream position plus materialization protection/history. D3 still requires explicit publication and repeated-track invariance. D10/Load scan evidence must migrate to immutable manifest coverage before removing runners. Retire onStore callback safety requirements only when the public API is removed; preserve declarative cascade, schema constraints and Mutation transaction boundaries.

The following are release obligations, not passing claims:

- SYN-7, real PostgreSQL: V03 track/read versus write transaction order, publication fence, unchanged repeated track, complete recipients/child invalidation, compacted receipt fallback frozen in the business transaction, retained manifest keys and capacity/expiry behavior. Fetch must not enroll; explicit Query track still occurs with snapshot-only responses and canceled requests.
- SYN-8, real SQLite: extend the independently authored native carrier traces through `ScenarioAdapter`; inject commit/constraint failures, reopen the actual file/process, and assert rows/evidence/layers/progress together. Add SQL relation/unique groups across page boundaries, accepted-local-failure retry, dropped response replay, tombstone retention, old incarnation/context responses, reset and compatible descriptor translation. No generic missing-FK rejection.
- SYN-8/V13: Alice plus Workspace A/B and two same-Stream files; isolate SQL, observation, query/once cache, request/await/Bootstrap/connection state and queue. Canonical path aliases, OS file locks and separate processes need actual filesystem tests. Same Call ID must not replay another binding's receipt.
- SYN-9, TypeScript/Dart/native packages: callback-before-input, async scope and unawaited operations, wrong/uncommitted handles, independent acts, mode/default normalization, once/refresh return semantics, generated inheritance, removed Load/onStore APIs, installation and reopen using published package artifacts.
- SYN-10 integration: replay neutral cases through assembled PostgreSQL→transport→SQLite→SDK adapters, then deterministic scheduling/seed and shrink. Measure slow Query versus sync, local transaction cost, coverage metadata and finite Bootstrap. The hand-authored symbolic/native traces remain fixed; the bounded generator below covers local-native intents only and the measurements establish no latency or capacity guarantee.

## Bounded native seeds and measurements

[`seeded04`](https://github.com/zanminwang/axton/blob/v0.4.2/crates/sim/tests/seeded04.rs) runs eight fixed seeds with 24 Set/Clear/reopen intents over Alice and two workspace-labelled files; two files deliberately share a Stream. The [independent expectation model](https://github.com/zanminwang/axton/blob/v0.4.2/crates/sim/tests/support/seeded04.rs) keeps desired device-only content and fixed no-Stream metadata, lowers each candidate to legal create/delete carriers and compares complete committed snapshots through the actual native adapter. It does not import production admission or calculate goldens from observed rows. The original symbolic and fourteen-step authored native traces remain separate.

Run `AXTON04_SEED=42 cargo test -p axton-sim --test seeded04 bounded_seeds_replay_full_committed_native_snapshots --locked` for one seed. A failure saves its seed/error and independently constructed original/reduced JSON scenarios in a unique temporary artifact, printing its path. Replay with `AXTON04_REPLAY=/path/to/artifact.json` and the same command without `AXTON04_SEED`. Reduction deletes intent blocks and rebuilds legal carriers plus independent expectations; it stops after 128 attempts or thirty seconds checked between attempts, recording budget exhaustion. An in-flight replay still has its native event deadline. Unexhausted reduction reaches a one-intent-deletion minimum; an exhausted result is only a smaller failing candidate. A controlled observation-corruption test verifies that reduction retains the required signal and that saved expectations replay successfully against the healthy real actor. This self-test is not a production defect.

This generator covers local content/order, file isolation and reopen only. Its clear of an already absent row is a no-op, and replacement Set is lowered to delete/create. It does not generate Mutation receipts, null reads, schema changes, manifests or arbitrary server publication schedules. Those remain the independently authored protocol/native/PG/SDK cases; no full V01–V13 seeded proof is claimed.

[`measure04`](https://github.com/zanminwang/axton/blob/v0.4.2/crates/sim/tests/measure04.rs) records three observations for callback transactions of 1/16/128/512 rows with 128-byte content per row, and authored strict manifest carriers of 0/16/128/512 identities. Transactions enter the actual actor callback capability and await native commit; manifests use Start/Page/Tail responses through normal host effects, require covered=total, captured tail and actual C, and verify each row's installed current protection/G. It writes no SQL C and calls no installer helper. `AXTON04_MEASUREMENTS=/path/results.json cargo test -p axton-sim --test measure04 --locked -- --nocapture` saves observations. Tests assert committed content/evidence/completion, never timing thresholds.

Transaction elapsed time spans task submission through committed completion, excluding Store open and verification reads; command bytes cover serialized write envelopes. Manifest elapsed time spans connect through the completion predicate and committed-reader barrier. Coverage bytes measure only the client's persisted coverage JSON. Response bytes measure the authored HTTP bodies, and SQLite+WAL bytes include business content and all client tables. **These do not measure server manifest identity/group rows or prove total Bootstrap metadata constant.** Manifest payload grows with identity count. There is no real network/PostgreSQL in this measurement carrier, no installed SDK overhead, and no backend capacity/latency promise. The separate real PG paused-Query and moving-tail fixtures prove progress while held work/writes exist, rather than a latency benchmark.
