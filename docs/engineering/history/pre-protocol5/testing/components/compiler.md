# Compiler tests

Verify that accepted schemas produce the intended descriptors and APIs, and invalid schemas fail with useful diagnostics. See [Compiler architecture](https://github.com/zanminwang/axton/blob/71b14195b897bc8a42f19e0a83d59dfe8fc76677/docs/engineering/architecture/compiler/README.md).

[Existing tests](https://github.com/zanminwang/axton/blob/71b14195b897bc8a42f19e0a83d59dfe8fc76677/crates/compiler/tests) cover parsing (`parse.rs`: declarations, positions, syntax-only errors), validation, mutation and model history, CLI output and emitter content.

```sh
cargo test -p axton-compiler --locked
```

Add a small schema fixture with an assertion on the resulting descriptor, generated output or diagnostic. When the claim is that generated code typechecks or runs, use [SDK integration tests](https://github.com/zanminwang/axton/blob/71b14195b897bc8a42f19e0a83d59dfe8fc76677/docs/engineering/testing/integration/bindings.md) as well.

Generated-language negative cases exist for TypeScript and Dart; see [SDK integration](https://github.com/zanminwang/axton/blob/71b14195b897bc8a42f19e0a83d59dfe8fc76677/docs/engineering/testing/integration/bindings.md).

Verified 2026-09-14: `cargo test -p axton-compiler --locked` passed (5 CLI, 12 compiler, 2 history tests) after the diagnostics and reserved-name changes.
