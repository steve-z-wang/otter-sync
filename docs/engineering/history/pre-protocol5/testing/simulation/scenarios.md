# Simulation scenarios

A named scenario shows one observable promise through an explicit sequence of actions and assertions. It should explain why the order matters, such as a page arriving before a receipt or a rejected mutation having dependents.

Existing [scenario tests](https://github.com/zanminwang/axton/blob/71b14195b897bc8a42f19e0a83d59dfe8fc76677/crates/sim/tests) are grouped into local writes, push, authority, distribution, reports and resilience. They use the same [Sim and Action types](https://github.com/zanminwang/axton/blob/8ad6b3efbf999f148b6dfe7278d7a2c6dd91b643/crates/sim/src/sim.rs) as the random runner.

```sh
cargo test -p axton-sim --test authority --locked
```

Choose a minimal model, stream and client setup. Apply the relevant actions, then assert visible records, stamps, cursors or pending work according to the promise. Run invariant checks at meaningful intermediate states as well.

Next review: connect each overall guarantee to named assertions and identify clauses not exercised by the existing scenarios.
