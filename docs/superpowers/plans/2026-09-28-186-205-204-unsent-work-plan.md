# Unsent Work Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An application enumerates and resolves its unsent work account-wide - refused acts with the act as submitted, acts blocked on a failed prerequisite, the pending count - through change streams, resolves it inside `client.transaction`, and a new requirement on a failed task inherits the failure ([#186](https://github.com/zanminwang/axton/issues/186), [#205](https://github.com/zanminwang/axton/issues/205), [#204](https://github.com/zanminwang/axton/issues/204)).

**Architecture:** The engine gains read models over `axton_rejection`, `axton_mutation` and `axton_mutation_prerequisite` (refused acts, failed acts), a multi-key task retry and a discard that records no refusal for the act itself. The client exposes them outside and inside a transaction. The runtime adds one observer kind, re-run after every commit like `watch` and published only when it differs, plus task and transaction commands; a transaction defers the Call completions and backoff resets its resolutions cause until the commit. SDKs wrap them as `client.rejections`, `client.failures`, `client.outbound`, `tx.rejections` and `tx.failures`; generated clients delegate to them.

**Tech Stack:** Rust client engine and runtime, SQLite tests, TypeScript client-js and React Native, Dart SDK, compiler emitter.
